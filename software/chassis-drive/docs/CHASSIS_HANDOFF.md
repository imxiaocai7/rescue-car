## 用户目标与项目边界

实现 Windows 电脑通过 Wi-Fi 向 ESP32-S3 发送控制信号，ESP32 经 UART 转交 STM32F407VET6，STM32 通过电机驱动模块驱动两台直流减速电机，使两轮差速底盘前进、后退、转向和停车。用户 2026-10-19 将驱动选择从 TB6612FNG 改为 L298N；旧实测记录仍属 TB6612 阶段。

底盘已经打印：两个电机各驱动一个普通橡胶轮，另有一个无动力辅助轮（牛眼轮）。不是麦克纳姆底盘。现阶段先实现电脑人工控制，后续再完善编码器闭环和运动精度。

本子项目不连接 OpenMV 摄像头、舵机或测距传感器，不做视觉、救援目标识别或自动规划。后续底盘工作在新建的专用对话开展。

## 最新已采用的接线与供电

两块板子分别使用自己的 USB 供电；STM32 用 Mini-USB，ESP32 用自身 USB。ST-Link 只接下载信号和地，3.3 V、5 V 输出均留空，两板电源轨不互接。

| 起点 | 终点 |
|---|---|
| ESP32 GPIO17，UART TX | STM32 PA3，USART2 RX |
| ESP32 GPIO18，UART RX | STM32 PA2，USART2 TX |
| ESP32 GND | STM32 GND |
| ST-Link SWDIO（外壳图 4 号） | STM32 PA13，P1 调试座 7 号 |
| ST-Link SWCLK（外壳图 2 号） | STM32 PA14，P1 调试座 9 号 |
| ST-Link GND（外壳图 5/6 号） | STM32 GND，P1 调试座 4 号 |

UART 使用 115200、8N1。PA3 就是板上 PA3 引脚，RX 是此固件为它配置的串口功能，不是另一个名为“PA3 RX”的接口。

用户最后确认通信线已接好；ESP32 重新接入后 COM8 恢复。驱动模块、电机和动力电池在当前通信验收阶段均未接入。不要把早期讨论过的电机引脚表当作当前已实现配置。

ST-Link 编号与 STM32 调试座编号不同，不能同号相连。已提供的 P1 图中 1 号为 3V3，2 号虽标 Vsupply 却画为 GND；本方案都不用。实物定位以标记和已核对图为准，不凭照片朝向猜针号。

调整杜邦线前两板断电，避免一块未供电时被另一块 UART 反向供电。STM32 的 Mini-USB 在本固件下只供电，不枚举 USB 串口。

- `pc/protocol.py`、`pc/probe.py`：电脑协议和测试工具，默认使用本机模拟器；真实目标必须显式指定地址和 `--allow-hardware`。
- 25 项软件测试此前通过，包括 Python/C 协议、网关和 TCP 故障场景；两板交叉编译通过。这里不是 2026-10-10 重新跑过测试的声明。

当前协议只有 PING 和 STOP 两种诊断操作，没有运动指令。请求 `CDP1`、16 字节；回复 `CDS1`、24 字节，含序号、STM32 uptime、固件标识 `0x20261007`、`NO_MOTOR_IMPLEMENTATION` 标记和 CRC32。

STOP 在此版本只是诊断请求，不能当作已实现的电机刹车。ESP32 只转发 STM32 的真实回复，不代答。网关一次等待一个请求，回复超时 400 ms，残帧 500 ms、空闲 3 s 关闭会话。详情以 `docs/PROTOCOL.md` 与源代码为准。

PC 报告 `hardware_verified: false` 表示未证明电气、停车和整车安全，即使未来真实通信成功也不是测试失败。
