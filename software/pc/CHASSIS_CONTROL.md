# 底盘手动控制：第一阶段软件

本阶段使用现有 `RCM1` 左右轮速度指令和 `RST1` 遥测协议，不修改或烧录板子。
模拟器只验证协议、序号与通信失效行为，不模拟真实 PI、电机电流、惯性、制动距离或轮胎打滑。

## 先用电脑控制界面（推荐）

在 `C:\Users\imxiaocai\Desktop\gc` 根目录运行：

```powershell
python software/pc/control_chassis.py --demo
```

也可以不带参数，默认仍为本地模拟。程序自动启动随机端口的本机模拟器，退出窗口时关闭。
只依赖 Python 标准库和 Tkinter，不需要 YOLO、摄像头、串口或 Wi-Fi。

1. 等待界面显示“已连接，未允许运动”，且“允许运动”按钮可用。
2. 点击“允许运动”，再按住 W/S 前进/后退，A/D 原地左转/右转。松开停止。
3. W+A / W+D 表示弧线转弯；相反按键同时按下时输出零速。
4. 可按住方向按钮操作，或用滑块调整速度。初始 80mm/s，上限 300mm/s；这些不是实车安全参数。
5. 空格、Esc、停止按钮、窗口失焦会取消运动授权。再次运行必须重新点击“允许运动”。
6. 授权前已经按住的方向键必须先松开再按，自动重复按键不会恢复旧动作。

界面显示目标、最近发送值、编码器估算轮速、累计计数、反馈年龄与指令确认序号。
模拟轮速基于合成轮径；外部连接未指定实测轮径时显示“未标定”，不会猜测你的轮径。
不需要轮距即可控制左右轮速度；此阶段不输出精确车体角速度，也不估计全局位姿。

## 独立运行本地模拟器

在仓库根目录运行：

```powershell
python software/pc/chassis_simulator.py
```

服务只监听 `127.0.0.1:5501`，不访问串口、ESP32 或任何硬件。按 Ctrl+C 退出。
每 50ms 输出一帧遥测；有效命令租约到期后归零，断开 TCP 不重置命令序号。
默认 75mm 轮径、1560 计数/圈仅用于合成编码器数据，**不是实际轮径标定**。
没有陀螺、测距或电池采样，相关字段标为无效。

故障注入示例（时间从模拟器启动算起）：

```powershell
python software/pc/chassis_simulator.py --drop-commands
python software/pc/chassis_simulator.py --mute-telemetry-after 10
python software/pc/chassis_simulator.py --emergency-stop-after 10
```

测试：

```powershell
python -m unittest discover -s software/pc -p "test_chassis_simulator.py" -v
```

另开终端连接这个模拟器（窗口打开后点击“连接”）：

```powershell
python software/pc/control_chassis.py --host 127.0.0.1 --port 5501 --wheel-diameter-mm 75
```

这里的 75mm 必须与模拟器的合成参数一致，仅用于演示。

## 电脑端的保护行为

- 正常控制最多 20Hz 发送，指令租约 300ms；等待确认时不连续堆积运动帧。停止零速可抢先发送。
- 收到新鲜、有效的双编码器遥测后，采用 STM32 上次接受序号 + 1 发零速；确认后仍保持未授权。
- 指令确认超过 200ms、遥测超过 300ms、首帧超过 800ms，或界面心跳超过 250ms，锁定故障。
- 重复/乱序遥测不刷新反馈年龄。板子复位、编码器无效、急停、其他控制端的序号会禁止运动。
- 故障或关闭时尝试发送一次零速并关闭通信；发送超时为 50ms。**不能保证零速送达**。
- 不自动重连、不自动恢复运动；重新连接后重新同步序号、确认零速并由操作者授权。

时间阈值是软件检查配置，不是 Windows 实时调度保证，更不是车身停稳时间。
RST1 的确认只表示命令被接收，不表示电机执行成功或停稳。
RCM1 租约从 STM32 接收时计算，没有发送端绝对截止时间、会话 ID 或硬件授权位；
本模块限制待确认指令堆积，但不能据此证明网关积压/延迟旧帧完全安全。
后续 STM32/ESP32 联调还要验证旧帧清理、超时关闭输出与实际停车行为。

## 实车接口暂不用于电机动力测试

非本机地址默认被拒绝。以后满足硬件验收条件时，才可显式启用：

```powershell
python software/pc/control_chassis.py --host 192.168.4.1 --port 5001 --allow-hardware
```

外部模式不会自动连接，要点击“连接”；地址应使用 ESP32 实际 IPv4 地址。
`--allow-hardware` 只是连接开关，不表示安全验收通过。实际轮径测量后再加
`--wheel-diameter-mm 实测值`。当前还没有 STM32 板级可烧录工程，不能用此程序直接驱动车辆。
图传端口 5000 不受修改；本轮没有改 ESP32 固件或网络配置。

电机 MG513P30_12V 的单个堵转电流为 3.2A；TB6612 的 3.2A 是 10ms 单次脉冲条件，
不是连续能力。电池满电电压、启动/负载电流、驱动容量、限流与电源切断措施确认前，不上动力电。
软件归零不是 STBY 硬件禁用，也不能替代硬件急停。

## 回归测试

本仓库已有 `.venv-vision`，包含旧 USB 测试所需的 pyserial；普通 Python 也能运行本模块，
但直接运行全项目测试可能因缺少 pyserial 而失败。在根目录运行：

```powershell
& .\.venv-vision\Scripts\python.exe -m unittest discover -s software/pc -p "test_*.py" -v
```

新增测试包括确定性模拟、协议错误/序号/租约、控制状态机、本机 TCP 集成和隐藏 Tk 窗口回调。
没有显示环境时，Tk 窗口测试跳过；本机 Windows 验证时不跳过。上述均不是实车测试。
