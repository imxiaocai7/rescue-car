# 救援视觉数据与标注约定

本文把比赛规则转换成 YOLO 检测类别和人工标注规则。类别按任务身份定义，颜色和尺寸只记录为初赛采集参考，不写入类别名。决赛的数量、形状、颜色、重量、大小和位置可能由现场任务另行公布，届时先更新任务映射，再补采相应样本。

## 类别与固定编号

| ID | 类别名 | 初赛外观参考 | 任务处理 |
|---:|---|---|---|
| 0 | `ordinary_material` | 绿色，约 40 mm 立方体 | 普通物资；首趟须单独转运 1 个，之后可与核心物资合运 |
| 1 | `core_material` | 黑色，约 40 mm 正三棱锥 | 核心物资；与普通物资合计每趟最多 3 个 |
| 2 | `casualty` | 橘色，约 80×40×40 mm 长方体 | 伤员；单独转运，每趟 1 个，目的区为伤员区 |
| 3 | `danger_object` | 浅蓝色，约 40 mm 立方体 | 危险目标；只避让，绝不作为转运目标 |
| 4 | `opponent_robot` | 对方救援机器人 | 动态障碍；避让，不主动接触或进入对方安全区 |

编号是标签文件中的 `class_id`，须与 [`rescue_classes.json`](rescue_classes.json) 保持一致。不得因颜色、摆放方向、材料批次或拍摄场地变化而重排编号。第四类以外的未知物体不应硬标成某一种救援物资；采集时保留并人工复核，运行时未映射类别按障碍处理。

## 图片和标签目录

把数据放在一个独立于代码版本库的大目录中，例如：

```text
dataset/rescue/
  images/
    train/
    val/
    test/
  labels/
    train/
    val/
    test/
```

每张图片对应一个同名 `.txt` 标签文件，目录结构保持一致。每一行标一个物体：

```text
class_id x_center y_center width height
```

坐标使用相对图片宽高归一化到 0–1 的 `xywh` 格式，类别编号从 0 开始。没有目标的纯背景图使用空标签文件。所有看得见且可辨认的危险目标也必须标出，不能当背景略过。

## 标注细则

- 每个实例单独画一个紧贴可见物体边缘的矩形框；多个相邻物体不能合并成一个框，也不能把机器人上的相机、轮子等部件另标成机器人目标。
- 物体被部分遮挡但仍能确认类别时，框住可见部分并保持同一套做法。目标存在但类别无法确认的图片先移出 train/val/test 集合并标记待复核；不能把它当成纯背景图。
- 球体、圆柱体和不同朝向的物资都按其图像可见外轮廓画框；不要按预期尺寸补画看不见的区域。
- 初赛采集应覆盖目标单独/成堆、不同朝向、距离、光照、地面纹理、遮挡和对方机器人出现等情况。只采明亮、居中、无遮挡的目标会让模型在赛场边缘场景失效。
- 验证集和测试集按独立采集场次、视频片段或布置场景划分。连续视频的相邻帧放在同一份划分里，避免近乎相同的画面同时进入训练集和测试集。
- 测试集只用于最终评估，不能反复据此调阈值或选模型；调参使用验证集。
- 尽量保留原始图片，不要在训练前只截取目标、抹除障碍或人工改变目标颜色。增强由训练程序执行，实拍测试集保持原样。

## 采集与模型验收

采图时记录相机分辨率、镜头/安装角度、拍摄距离、光照、物体种类和摆放状态。训练数据要接近比赛时 OpenMV 的实际画面；相机分辨率或安装改变后需重新评估投影标定和识别效果。

每个类别都要检查实例数、漏标和混淆。模型评估至少查看逐类 precision、recall、mAP、混淆矩阵及典型漏检图。危险目标漏检、伤员与物资混淆、误把背景当救援目标，都要单独复核；整体 mAP 不能替代逐类检查。模型通过离线评估后，还要在实时视频上测检出率、推理延迟和连续帧稳定性，才能接入自主决策。

## 数据集命令

从仓库根目录运行，数据目录必须与源代码分开备份：

```powershell
python -m pip install -r software/pc/requirements-vision.txt -r software/pc/requirements-yolo.txt
python software/pc/vision_workflow.py audit --dataset-root dataset/rescue
python software/pc/vision_workflow.py train --dataset-root dataset/rescue --model yolo26n.pt
python software/pc/vision_workflow.py evaluate --dataset-root dataset/rescue --weights runs/rescue/rescue/weights/best.pt --split test
```

首次训练若使用模型名称而非本地权重文件，需要联网下载预训练权重。若尚未准备测试集，可先用 `--split val` 做阶段评估；正式结果仍应留出未参与调参的测试集。训练会检查全部五类是否同时出现在训练集和验证集中；早期小数据实验可显式加 `--allow-incomplete-classes`，但此时缺样类别的识别结果不能视为有效。
